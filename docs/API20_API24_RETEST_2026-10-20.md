# API20/API24 补测环境核查

后续决断：组长因无 API20/API24 鸿蒙 PC 设备，已改为[收窄至 API23 已验证范围](API23_SUPPORT_SCOPE_2026-10-20.md)。下述“选择补测”是当时的核查快照，不再是当前执行方案；两端从未被测成通过。

日期：2026-10-20。当时组长选择**补测 API20 与 API24**，不以收窄声明替代测试。当时工程 [`app/build-profile.json5`](../app/build-profile.json5) 为最低 `6.0.0(20)`、目标 `6.1.1(24)`；本次环境核查未修改该配置或签名包。当前配置与执行方案以上方后续决断为准。

本机 `hdc list targets -v` 仅列出一台 USB 设备 `HAD-W32`，`param get const.ohos.apiversion` 为 **23**。这台设备上的最新包已通过真实五阶段、显式断网、UI 临界观察及[12 项页面数值复核](PR17_NUMERIC_UI_ACCEPTANCE_2026-10-20.md)，但 API23 不能充当 API20 或 API24 的运行证据。

本机有模拟器**程序**（26.0.0.402），但在已安装华为工具及当前用户本地数据目录中未找到可运行的 `.img`、`.qcow2`、`.vdi` 或 `.vmdk` 系统镜像；`hdc` 也未列出模拟器。最新 HAP 只包含 `libs/arm64-v8a` 原生库（219 项，包括 `libgsas_core.so`），即使取得不匹配架构的模拟器镜像，也不能据此验证完整科学计算。SDK 文件或镜像目录名不等于实际 API20/API24 运行环境。

**结果：API20 未执行；API24 未执行。** 补测仍需分别连接可运行该 ARM64 HAP 的 API20、API24 HarmonyOS PC 设备或等效 ARM64 系统镜像。对每一环境先记录设备型号、系统/API、HAP SHA-256 与签名/安装结果，再跑启动、五输入、真实五阶段、结果/导出及重启恢复；实际失败须留原始错误，不得用 API23 结果覆盖。取得两套同包记录并复核后才可将兼容性矩阵标为完成。`releaseApproved=false` 保持不变。
